# ADS-B decoder integration and verification

The unified Decoder list's `adsb` entry is backed by the embedded FlightAware dump1090-fa core (upstream `0339a57b89cd6e61856cbb13ae342c31ae7be5ac`, GPL-2.0-or-later), using the same single receiver's tuned IQ tap. Source attribution, modifications and licensing are in `native/third_party/dump1090/PROVENANCE.md`; the OpenWebRX+ chain audit is `STATUS-adsb-audit.md`. The DSP tap, snapshot contract, native tracking, UI, and generated-IQ oracle were integrated in the five ADS-B child tasks. See `STATUS-adsb-backend.md`, `STATUS-adsb-ui.md`, `STATUS-adsb-oracle.md`, and `docs/adsb-snapshot-v1.md` for their test cases and fidelity limits.

The existing receiver remains the only USB owner and tuner controller. At a 2.4 MS/s device rate, the user's VFO IQ reaches dump1090 without decimation; supported higher rates resample natively. Too little bandwidth or a displaced VFO window is reported as not ready. Normal user controls explicitly set 1090 MHz or 2.4 MS/s; selecting ADS-B never does. Only bounded one-second aircraft snapshots cross FFI, and voice audio is silent during the selected data decoder. The list shows last-seen, callsign, altitude and expandable details, handles stale/expired tracks and optional receiver coordinates, and has no map. The OpenWebRX+ invocation does not enable CRC fixing by default; the embedded core matches that default. No location or detected aircraft is synthesized.

## Host RTL-SDR check and remaining limits

The attached RTL2838 Blog V4 was opened through `sdr_host_open_usb` with the actual v3 decoder pipeline, tuned to 1,090,000,000 Hz at 2,400,000 samples/s (38.0 dB gain, null/muted host sink). A temporary C diagnostic in the ignored `build/native-host-tests/` directory selected `adsb` and polled 30 seconds of native FIFO snapshots: snapshot state RUNNING, no reported v3 error, 72,044,544 input and processed complex samples, zero native ring drops, 30 bounded snapshots, zero aircraft, zero messages/s, zero nonsilent audio frames. Process CPU time was 3.96 seconds over 30.03 wall seconds, with Debug host build and the DSP, decoder and null audio sink all included; this is not an isolated decoder-only benchmark. The USB driver also printed `rtlsdr_demod_write_reg failed with -9` / `r82xx_write: i2c wr failed=-9 reg=06 len=1`; the stream counters alone do not prove clean tuner RF behavior. A known 1090 MHz signal/antenna and a longer live-air check are needed before claiming on-air aircraft reception or device-visible aircraft UI acceptance. No Linux ADS-B panel screenshot was obtained; widget tests, not a desktop visual run, cover layout. No Android phone was touched; on-device throughput and audible/visual behavior remain unverified. The full OpenWebRX+ JSON parser/service-process replay is also unverified due to the host Python `distutils` gap and upstream finite-file timestamp issue described in `STATUS-adsb-oracle.md`. Mode A/C, surface CPR, multi-ICAO interference and weak/noisy RF still lack an IQ oracle.
