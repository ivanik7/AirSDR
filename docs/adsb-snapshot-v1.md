# ADS-B IQ and aircraft snapshot contract (v1)

This is the contract for the subsequent dump1090 backend and Flutter aircraft-list work. The present tap does not install an ADS-B decoder: registry `available=0` until the real backend is linked. See `STATUS-adsb-audit.md` for pinned source behavior and license boundaries.

## Input and lifecycle

Registry ID `adsb`, `Input::raw_iq` / `SDR_DECODER_RAW_IQ`, `required_rate_hz=2400000`, `Result::aircraft` / `SDR_DECODER_AIRCRAFT`, `exclusive_receiver=false`, demodulation mode independent. It uses the **existing** single receiver at the user's tuned frequency (`center_frequency_hz + vfo_offset_hz`), with no SDR acquisition, tuner gain/rate/frequency changes, subprocess or decoder-owned USB handle. Selecting a data decoder silences voice output in the native consume loop; the UI need not select a synthetic voice mode. Quick tune and rate changes, if offered, must go through normal explicit radio controls.

The CU8 ingress is mapped to complex float `(byte - 127.5) / 127.5`; the decoder branch mixes the user's VFO offset to baseband. At 2,400,000 input complex samples/s, it passes all complex samples directly, without integer decimation. For higher source rates with the complete +/-1.2 MHz window (`abs(vfo_offset_hz) + 1200000 <= sample_rate/2`), a stateful native 48-tap/128-phase low-pass converter (1.05 MHz cutoff) outputs exactly 2,400,000 complex float pairs/s, continuous across input blocks. A rate below 2.4 MS/s or a VFO window extending beyond the source Nyquist band is **not ready**: selection returns `SDR_UNSUPPORTED`, and an already attached decoder's DSP tap reports zero rate and receives no IQ. Do not silently change sample rate or widen the hardware bandwidth. The source's *actual analog/driver passband* is not represented by the v3 controls; this digital window check cannot prove RF bandwidth on every device. `bandwidth_hz` in v3 is the voice channel filter, not the device bandwidth and must not gate this raw tap.

The backend receives borrowed interleaved float I,Q in `Decoder::process`, with frame count measured in **complex** samples. At the dump1090 boundary reproduce the OpenWebRX+ `COMPLEX_FLOAT -> COMPLEX_SHORT` conversion: clamp to signed 16-bit range and scale each component by 32767, then feed interleaved signed short I,Q (SC16, **not** Q11, CU8, audio or magnitude-only data) to upstream dump1090's magnitude/demodulator. Compare the quantization and actual upstream magnitude flavor in an oracle test before claiming parity. Retune (including LO and VFO moves), mode change, rate change, stream start/stop, decoder attach/detach and stale-block reattachment reset DSP filter/overlap and backend track state. Old queued events are invalidated by the handle; generation and sequence in `SdrDecoderEvent` protect the consumer against stale results. No IQ or audio is delivered to Dart.

## JSON payload

Publish **one complete snapshot at most once per second** from native track state while receiving, including an empty `aircraft` array when tracks expire. Use the existing `SdrDecoderEvent` FIFO, `kind=SDR_DECODER_AIRCRAFT`, `payload_bytes<=65536`, `sequence` and `stream_generation`. UTF-8 JSON object:

    {"version":1,"source":"adsb","timestamp_ms":1730000000000,
     "input_rate_hz":2400000,"message_rate":4.0,"crc_fixed":0,
     "aircraft":[{"icao":"ABC123","last_seen_ms":1730000000000,
       "messages":7,"rssi":-28.5,"callsign":"EXAMPLE1",
       "squawk":"1234","altitude_ft":34000,"ground_speed_kt":420.5,
       "track_deg":95.4,"vertical_rate_fpm":640,
       "latitude":51.5,"longitude":-0.1}]}

`timestamp_ms` is the epoch-ms snapshot time; `last_seen_ms` is the epoch-ms time of the last accepted aircraft message, not an elapsed-age field. `message_rate` is the count of accepted messages in the most recent one-second interval (messages/s, numeric); `crc_fixed` is a cumulative count of messages actually repaired in the current decoder session, reset on every decoder reset. Default OpenWebRX+ invokes dump1090 without `--fix`: correction is disabled by default and this count is zero; a future correction option must be explicitly configured and tested. Do not conflate CRC failures, preambles or discarded packets with accepted messages. A decoded frame is never forwarded as its own Dart event.

`aircraft` contains at most **128** tracks, sorted by newest last-seen first (ICAO lexical tie-break). Drop the oldest beyond the cap; do not truncate JSON or emit an invalid partial snapshot. Serialize only upstream reliable tracks and honor dump1090's per-field validity/expiry, its 300-second reliable-track TTL and periodic pruning. `icao` is an uppercase six-digit hex string, with a leading `~` for non-ICAO addresses when upstream uses it; the literal `icao` identifies the track and must not be guessed from a callsign. `callsign` is the trimmed upstream flight string and `squawk` is a **four-digit string** preserving leading zeroes. `altitude_ft` prefers valid geometric altitude, then barometric (`ground` = 0); `ground_speed_kt` is present only for valid GS (optional `airspeed_kt` may represent TAS or IAS with an explicit `airspeed_source` of `tas|ias`). `vertical_rate_fpm` prefers geometric, then barometric; `track_deg` is present only for valid ground track (optional `heading_deg` may represent true or magnetic heading with explicit `heading_source`). Do not label heading as ground track or airspeed as ground speed. `latitude` and `longitude` are present only **together** when position is valid, in WGS84 decimal degrees. `rssi` is the upstream eight-message dBFS power estimate, not an arbitrary UI meter. `messages` is a nonnegative accepted-message count for this track. All optional fields are **omitted** when unknown or expired, never fabricated as 0, empty string or null. Units remain feet, knots and ft/min even if dump1090's `--metric` presentation flag is used by the oracle.

If 128 entries would exceed the ABI's 64 KiB payload limit, drop oldest entries until the full JSON fits; never forward individual raw messages or fragment a snapshot. The native FIFO remains bounded to 256 events and drops oldest events with its existing `dropped_events` counter. Dart replaces its list from each coherent generation-stamped snapshot and does not infer additional aircraft when an event is lost. On a tune/mode/generation reset, clear visible aircraft immediately rather than displaying stale tracks while waiting for the next snapshot. Before a decoder is installed, or when the rate/window is insufficient, show a not-ready state from descriptor availability / select result and current radio controls; do not claim a live stream from an empty snapshot. There is no new v3 ABI struct or FFI stream.

## Verification boundary

The IQ tap/resampler and its lifecycle are covered by `sdrcore_adsb_tap`; registry metadata by `sdrcore_decoder_abi`. The separate backend task must verify SC16 conversion, actual dump1090 demodulation/tracking, snapshot size and expiry, periodic emission, and oracle comparison on identical IQ. The Flutter task must validate the JSON schema and rejected/insufficient-rate UI on a narrow layout. Host tap tests alone do not establish live ADS-B reception, Android performance, or RF analog bandwidth.
