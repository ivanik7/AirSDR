# ADS-B aircraft UI

The Decoder tab's ADS-B panel consumes only the bounded `SDR_DECODER_AIRCRAFT` v1 FIFO snapshots. It replaces its list on each complete generation-matched snapshot and clears it on selection, tune/VFO/mode/rate, stream-stop and generation changes. Malformed or oversized snapshots do not create aircraft. The list defaults to newest last-seen first, optionally sorts positioned aircraft by distance from manually configured receiver coordinates (stored in shared preferences), fades tracks older than 60 seconds, and removes tracks at the upstream 300-second reliable-track TTL. Details expand in place. No location, aircraft or map is inferred.

A rate below 2.4 MS/s or an insufficient VFO window shows `not ready: set sample rate 2.4 MS/s`; the explicit rate button uses `RadioController.setSampleRate` with a supported device rate, the recenter button uses `CenteredReceiver.tune`, and the 1090 MHz button uses the same tune path. None of these actions are automatic. The panel shows the native message-rate and CRC-fixed counters, current IQ rate, dropped FIFO events, and decoder status. Voice audio remains silent for a selected raw-IQ decoder at the native sink: `sdrcore.cpp` zeroes the output frames, and `sdrcore_decoder_abi` checks that synthetic-stream audio frames advance while non-silent frames do not.

Host verification: `flutter analyze` (no issues), `flutter test --concurrency=1` (490 passed, 17 skipped), `flutter build linux --debug` and `flutter build apk --debug` succeeded. A Debug CMake/CTest run first found an upstream Mode A/C reverse-table assertion on repeated decoder initialization; `modeACInit()` now runs once per process while session state still resets. The native ADS-B backend and silence CTests passed afterward. No actual aircraft reception, host visual RF acceptance, Android phone audio or recorded-IQ oracle parity is claimed here; the latter is covered in `docs/status/adsb-oracle.md`.
