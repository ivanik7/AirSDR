# STATUS — worker `dsp` (branch `wip/dsp`)

Port of the SDR++ DSP core (`~/prj/sdrpp/core/src/dsp` @8c9f5ee) to Dart, in `lib/sdrpp/dsp/`.
Scope: docs/02 §6.1–6.3, items 1–32 and 34. The port is synchronous and single-isolate. Buffers are
`Float32List`, with complex and stereo samples interleaved. Hot loops have Float32x4 kernels.

### C++ golden oracle
`tool/oracle/run_oracle.sh` compiles `tool/oracle/dsp_oracle.cpp` with g++. The program includes the **real SDR++
headers** and a scalar VOLK stub (`tool/oracle/volk_stub/volk/volk.h`). It dumps inputs and outputs to
`test/sdrpp/dsp/golden/*.f32` (≈3 MB, committed). The tests compare the Dart output against these dumps.

## Tests
Command: `source ~/prj/env.sh && flutter test test/sdrpp/dsp` → **139 tests, all passed**.
`flutter analyze lib/sdrpp test/sdrpp tool/dsp_lib_bench.dart tool/gen_decim_taps.dart` → **No issues found**.

- `kernels/kernels_test.dart`: the SIMD and scalar kernels agree with a reference for every alignment. The rotator matches e^(jωn), and its output is bit-exact under chunking.
- `fft/fft_test.dart`: compared against a naive DFT for n ≤ 512. Sizes 1024..65536 are tested for the tone bin, inverse round-trip and in-place operation, and the plan cache is checked.
- `taps/taps_test.dart`: all windows and all tap configurations match C++ golden within ≤1e-7 (2e-7 for complex). The decim plan table is checked, and the polyphase bank matches bit-exactly.
- `filter/filter_multirate_test.dart`:
  - Golden tests cover FIR (RR/CR/CC), setTaps continuity, DecimatingFIR, PowerDecimator (×2..×256), Polyphase 5/6, and RationalResampler (7 rate pairs plus stereo). Each is run with SIMD and scalar kernels.
  - **Block-boundary invariance** is bit-exact with scalar kernels, comparing random chunks against a single block.
  - Tone tests check passband amplitude and frequency, and stop-band rejection below −60/−70 dB.
- `channel/channel_loop_test.dart`:
  - Golden tests cover RxVFO, DCBlocker, AGC (with the look-ahead burst) and NoiseBlanker.
  - RxVFO is also checked with a tone and for chunk invariance.
  - PLL: compared against golden (<2e-3, see Notes), plus a lock test.
  - PowerSquelch and xlator continuity are tested.
- `demod/demod_test.dart`:
  - Golden tests cover Quadrature, BroadcastFM mono and stereo, FM (NFM), AM (both AGC modes), SSB (USB/LSB/DSB) and CW.
  - Tone tests from 02 §6.5:
    - FM tone → sine with the correct amplitude and frequency.
    - Stereo with an L-only tone: L = 0.9 and R < 0.01, separation > 35 dB.
    - AM → 1 kHz.
    - USB/LSB carrier + 1 kHz → 1 kHz.
    - CW carrier → 800 Hz.
  - BroadcastFM stereo output is bit-exact under chunking.
- `core_test.dart`: math helpers, ops/convert, Delay, DspStream, Chain (with a multirate block and enable/disable), RingBuffer, Reshaper (positive, zero and negative skip), Packer, Volume.

## Notes / deliberate deviations (docs/02 §6.6 preserved)
- **FIR:** correlation indexing is kept, with the complex band-pass pre-flipped as in SDR++. The polyphase bank uses the reversed phase index and the §3.6 update order. RationalResampler takes the gcd of the rounded rates, and its prototype is `lowPass(min/2, ·0.1)·interp`. The AGC starts with `initGain=∞`, i.e. `amp=0`. The xlator in RxVFO is `−offset`. All of this is verified by the goldens.
- **Rotator:** phase and delta are kept in double, but the delta is rounded to float32 as in the C++ `lv_32fc_t`. The phase is renormalised every 512 absolute samples, so the output is chunk-independent. VOLK renormalises per call, so this is an intentional difference.
- **Scalar dot products** accumulate in double. They are deterministic and chunk-invariant. The SIMD variants accumulate in float32x4 and differ from scalar by about 1e-6 relative, so the tests use a tolerance for them.
- **Deviations from C++ goldens:**
  - PLL and BroadcastFM stereo differ by up to ~2e-3 / 5e-3. Dart computes `atan2`/`cos`/`sin` in double, while C++ uses the float library calls, and the small difference propagates through the loop. Separation and lock behaviour are identical.
  - All other blocks match within 1e-5 relative.
- **AGC look-ahead:** when the signal clips, the AGC's output depends on block boundaries, exactly as in C++. That is why it has no invariance test.
- **Buffer sizing:**
  - `RationalResampler` and `RxVFO`: the output buffer must hold `maxOutput(count)`, which is at least `count`, because the pre-decimator writes its intermediate result into the output buffer, as C++ does.
  - `FIR`: history buffers grow on demand instead of the fixed C++ `STREAM_BUFFER_SIZE`.
- **Test layout:** the tests are grouped by stage rather than strictly mirroring every `lib/` file:
  - `filter/` covers `multirate/`.
  - `channel/` covers `loop/`, `correction/` and `noise_reduction/`.
  - `core_test` covers `buffer/`, `math/`, `audio/`, `stream` and `chain`.
