# MeshCore decoder contract (v1)

## Source boundary

OpenWebRX+ `f1e0d1a` runs `lorarx -i /dev/stdin -r 1000000 -f f32 -v -N -Q -H 5 -W 50 -b 6 -s 7 -s 8 -j /dev/stdout` by default; `meshcore_bw` selects bandwidth index. `owrx/lora.py::LoraParser` adds `mode: "LORA"`, `freq` if known and otherwise leaves the base64 payload and PHY fields untouched. It does **not** decode MeshCore packets. The app uses the existing exact 1 MS/s tuned-VFO tap and embedded OE5DXL lorarx (`native/third_party/lorarx/`, GPL-2.0-or-later) with those options. The MeshCore packet interpretation is an additive extension based on MeshCore firmware `81dbae592ffad40b4212bc0b37e82b38da08f4bc` (MIT, `license.txt`), not an OpenWebRX+ packet-parser port. The original firmware's `Packet::{readFrom,writeTo}`, `Mesh::{createAdvert,createGroupDatagram,onRecvPacket}`, `Utils::{encryptThenMAC,MACThenDecrypt}` and `BaseChatMesh::{addChannel,onGroupDataRecv}` are the packet/crypto oracle; preserve relevant original files/notices where feasible, and document adapters and parity. `docs/packet_format.md` and `docs/payloads.md` document wire fields. The public key (hex) and position in an ADVERT must not be treated as authenticated until the Ed25519 signature of `[pubkey][timestamp LE][appdata]` verifies. A bad signature may be logged as invalid but must not update the trusted node list.

## Native extension and settings

Registry ID `meshcore`, input `baseband`, required rate 1000000, result `message`, nonexclusive. Use the existing DSP tap, FIFO, silence and lifecycle; no USB/source-rate ownership. Settings envelope is `{"version":1,"settings":{"bandwidth":"6","channels":[{"name":"Ops","secret":"<32-or-64-hex-digits>"}]}}`. Bandwidth is one of `"6"` (62.5 kHz, default, OpenWebRX+), `"7"` (125 kHz), `"8"` (250 kHz), `"9"` (500 kHz). lorarx scans SF7 and SF8 as OpenWebRX+ does; it reads the explicit-header CR5..CR8 and does not force one. `channels` is at most eight entries, each named (1..32 UTF-8 bytes), unique and carrying exactly 16 or 32 secret bytes in hex; the public channel is always included using the firmware-published key `8b3387e9c5cdea6ac9e5edbaa115cd72`, and never echoed as a secret. For each key, channel hash is SHA256(key bytes)[0]; encryption uses AES-128-ECB with the first 16 bytes of a 32-byte secret (zero-padded for 128-bit keys); MAC is the first two bytes of HMAC-SHA256 keyed by the full 32-byte padded secret over the ciphertext, then decrypt fixed 16-byte blocks. No unauthenticated plaintext. Secrets can be saved with favorites but must not appear in event JSON, logs, errors or UI detail.

The backend uses the same global lorarx PHY owner as Meshtastic: refactor ownership/callback into a small shared driver or otherwise ensure switching decoders before old-instance destruction cannot wipe or route frames to the wrong parser. An exact 1 MS/s tap is accepted only when user sample rate and VFO window cover it; otherwise select returns not ready (do not retune). Retune, rate and generation changes reset parser/PHY and drop stale queue entries. Backend event size <=64 KiB; FIFO <=256, oldest drop counted.

## Wire/event schema

Each CRC-valid lorarx frame (`crc:1`) yields at most one JSON `message` event, even when packet payload is malformed; CRC-invalid frames are ignored. Canonical event fields: `{"mode":"MeshCore","timestamp":<Unix ms>,"freq":<tuned Hz>,"phy":{"crc":1,"sf":7,"bw":62.5,"cr":8,"level":...,"snr":...},"raw":"<packet hex>","header":{"version":1,"route":1,"type":4,"type_name":"ADVERT","transport_codes":[...]?},"path":{"hash_size":1,"hashes":["AB",...]},"payload":{...}}`. Unknown measurements are omitted, never fabricated or labeled calibrated RSSI. A header of version !=1, reserved hash size 4, >64 path bytes, >184 payload bytes, missing payload or truncated transport/path is `"error":"malformed_packet"` (or `unsupported_version`) without speculative payload fields. Hex is uppercase. Header type names follow `src/Packet.h`; transport codes appear only for route 0/3 (LE uint16). An ADVERT with >=100 payload bytes includes public key, sender timestamp, signature validity, appdata flags, optional signed int32 lat/lon scaled by 1e6, optional feature words, UTF-8 name; only valid signatures yield trusted `advert` fields for node list. ACK includes LE checksum when >=4 bytes. GRP_TXT includes channel hash and `encrypted:true` unless a configured hash-matching key passes MAC; verified plaintext has sender timestamp, text type/attempt and text from byte 5 through first zero padding; its sender name is **unverified text**, not an authenticated node identity. Group data and private TXT_MSG remain encrypted or opaque unless correctly authenticated; never pretend private messages can be decrypted without a node identity. Unknown types preserve raw payload hex.

UI uses one catalog row, selected-only panel and bounded session-local packet/message/node logs. Node rows only from verified ADVERTs; public/custom group messages only after MAC verification. Detail tap shows full event JSON excluding secrets. Native `level` is relative, not RSSI dBm. Quick tune calls the normal `CenteredReceiver.tune` path and does not silently change bandwidth; suggested radio settings should come from documented current MeshCore API and clearly distinguish region/regulatory suitability.

## Acceptance and parity

RED tests before implementation: firmware-derived packet/crypto/signature vectors; lorarx SF7/8, 62.5-kHz, private sync 0x12 IQ with identical `loratx` recording through upstream CLI and embedded receiver chain; malformed bounds + wrong channel MAC + retune; Dart FFI/event/panel at 344dp and wide, preset round trip without secret leakage. Compare OpenWebRX+ generic LoraParser output on the **same** lorarx JSON and compare firmware Packet/Utils behavior on the **same** packet vectors. Host RTL-SDR and emulator checks when available, no physical phone. Record CPU, APK size delta and any unverified behavior.
