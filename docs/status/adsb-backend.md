# Embedded ADS-B backend (native)

FlightAware dump1090-fa `0339a57b89cd6e61856cbb13ae342c31ae7be5ac` is built as a decode-only static library from `native/third_party/dump1090/`. Full upstream GPL-2.0-or-later license/attribution, exact source list and the two narrow source edits are in `native/third_party/dump1090/PROVENANCE.md`. The linked C code retains upstream 2.4 MS/s demodulation (including Mode A/C), SC16 magnitude, Mode S/CRC, CPR, Comm-B, ICAO filter and track policies. No subprocess, network server, file writer, second SDR handle or tuner control is linked.

`native/src/decoder/adsb.cpp` receives the previously implemented tuned 2.4 MS/s complex-float tap, quantizes components to SC16 (32767 scale), calls upstream's portable generic starch magnitude conversion and runs the original overlapping magnitude-block demodulators. It initializes upstream CRC/filter/Mode A/C tables, retains its native track list, performs periodic filter/track expiry, and emits at most one complete `aircraft` JSON event per elapsed second. Snapshot metadata and optional fields follow `docs/adsb-snapshot-v1.md`: at most 128 reliable aircraft newest-first, invalid fields omitted, 64 KiB byte cap, 1 Hz message count, current-session correction count (zero by default). All decoder state, outstanding snapshot and Mode A/C repetition history are cleared at receiver reset; upstream's global-state design permits only one backend instance at a time. Selection with a second handle returns unsupported instead of corrupting the first track list.

## Behavioral boundary

- The default OpenWebRX+ invocation does **not** pass `--fix`; the adapter keeps zero-bit-error correction by default and rejects unknown settings instead of presenting an unimplemented correction switch. The vendored CRC correction tables and implementation remain intact for future explicit configuration.
- This build selects dump1090's portable generic magnitude flavor. Upstream host builds may choose x86 AVX2 and arm64 builds may choose NEON, potentially producing small quantization/RSSI differences. Native 2.4 MS/s resampling or VFO mixing before SC16 conversion differs from OpenWebRX+'s direct centered SC16 stream; those differences need oracle comparison on identical IQ.
- No receiver GPS location is supplied implicitly. Without an explicitly configured location, relative/surface CPR results that require a receiver position are unavailable; airborne global CPR remains available. Distance, country/registration enrichment and OpenWebRX+'s global aircraft manager are UI-layer/future work, not fields of the v1 native snapshot.
- The in-process snapshot replaces OpenWebRX+'s `/tmp/dump1090/aircraft.json` mtime polling. It reports a complete bounded list even when empty, unlike OpenWebRX+'s file parser which conditionally publishes non-empty updates. The native FIFO handles generation and dropped events.
- This task verified the Linux decoder and Android debug native link, not live RF ADS-B reception, reference-CLI frame parity on recorded IQ, Android release performance or a visible aircraft UI. The downstream oracle/QA and aircraft UI tasks own those gates.

## Local verification

The `sdrcore_decoder_abi` assertion for ADS-B availability failed before the backend was linked, then passed after registration. `sdrcore_adsb_backend` decodes two published CRC-correct DF17 CPR frames through upstream `decodeModesMessage`, checks upstream reliability/position and a one-second JSON event, checks single-owner enforcement and reset clearing track/event state. The downstream parity check must additionally run the **demodulator on the same IQ recordings as upstream's executable**; direct Mode S frame tests do not establish IQ demodulation parity.

Commands run in the task worktree: `cmake -S native -B <scratch>/adsb-build -DCMAKE_BUILD_TYPE=Release`, `cmake --build <scratch>/adsb-build -j3`, `ctest --test-dir <scratch>/adsb-build -j2 --output-on-failure` (28/28), `flutter analyze` (no issues), `flutter test --concurrency=1` (486 passed, 17 skipped), `SDRCORE_HOST_LIBRARY=<scratch>/adsb-build/libsdrcore.so flutter test test/native/native_decoder_api_test.dart` (4 passed), `flutter build linux --debug` and `flutter build apk --debug` (both succeeded). The project was not installed on the phone.
