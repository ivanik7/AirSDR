# Native rtl_433 status

The upstream rtl_433 protocol and demodulation sources are embedded in `libsdrcore` (source and license: `native/third_party/rtl_433/PROVENANCE.md`). No decoder subprocess, independent tuner, or IQ/PCM transfer through Dart is used. The existing VFO's DSP worker runs a separate translated/filter-decimated complex-IQ branch at the integer rate nearest 250 kS/s (e.g. 240 kS/s at 2.4 MS/s or 250 kS/s at 2.5 MS/s), while the existing spectrum continues. An unsuitable source rate is rejected rather than changing the tuner. Selecting rtl_433 silences voice output; selecting a voice row restores it. Normal frequency controls and presets remain authoritative.

`{"version":1,"settings":{}}` is the only supported decoder config. Frequency is not a decoder option. Native events are JSON in the upstream field format, with relative input sample time and level metrics; frequency metadata is omitted because the decoder callback does not receive the tuned RF frequency. A 256-entry native FIFO returns oldest-first and counts overflow; the session has a 500-row newest-first log. Retune/stop/deselect/generation changes invalidate events. The log is not persisted. The screen shows tuning/rate, dropped events, model/id/channel/measurements, local receipt time, and expandable raw JSON; no data decoders except rtl_433 are marked working.

## Verification on debian-ai

- `native/tests/run_host_tests.sh`: 20/20 CTest cases plus standalone lifecycle/checksum/libusb/oracle checks passed. `SDRCORE_HOST_LIBRARY=build/native-host-tests/libsdrcore.so SDRCORE_V3_PROBE_LIBRARY=build/native-host-tests/libsdrcore.so flutter test test/native --concurrency=1`: 114 passed, 3 hardware skips.
- OpenWebRX+ parity: OpenWebRX+'s `IsmDemodulator` runs `rtl_433 -r cf32:- -s 250000 -A -Y autolevel -F json -M time:unix [-M level]` on a 250 kS/s channel (`csdr-plus/module/toolbox.py`, `owrx/dsp.py`). The adapter reproduces that input path in-process: CF32 converted exactly as upstream's cf32 reader (truncate x*INT16_MAX, clamp) into CS16, upstream DEFAULT_BUF_LENGTH framing (65536 complex samples per `push_sdr_flow`), and `auto_level=1`. `-A` (pulse analyzer printout) and wall-clock `time` are not reproduced.
- `RTL433_ENGINE_BINARY=build/native-host-tests/sdrcore_rtl433_engine_test python3 native/tests/rtl433_oracle.py --limit 400`: 400/400 payload matches against the pinned upstream CLI run with OpenWebRX+'s arguments (`cf32`, `-Y autolevel`) on the SAME float IQ; 294 decoded captures / 584 events.
- `python3 native/tests/rtl433_oracle.py --tap --limit 400`: 400/400. Each 250 kS/s corpus file is zero-order interpolated to 2.5 MS/s and run through the real receiver tuned-VFO FIR /10 branch; the exact CF32 the engine received is dumped and fed to the OpenWebRX+-style CLI invocation: identical payloads; 276 decoded captures / 485 events. Separately, 357/400 also equal the CLI on the unfiltered original capture: the channel filter + synthetic interpolation changes marginal pulses (weak remotes lose repeats; a few counters differ). That is a property of the input signal after filtering, not of the decoder; OpenWebRX+ also filters to 250 kS/s with its own (csdr) chain, which is not bit-identical to ours and was not run here (csdr/pycsdr not built on this host).
- Earlier 180/200 tap result was an oracle bug: upstream `fileformat.c` parses format tokens from the whole path, and random tempdir names occasionally contained a lone `i`/`q`; the oracle now forces the format prefix.
- AddressSanitizer with leak detection: native engine contract, actual Alps-FWB1U545 capture, and baseband-tap test passed. This does not establish full TSan coverage.
- `flutter analyze` clean; `flutter test --concurrency=1` passed 425 tests with 14 skips in the unconfigured environment; real native FFI run above passed separately. Linux debug, Android debug APK and Android arm64 release APK built successfully. Xvfb Linux GUI stayed running for 12 seconds (timeout 124); no Flutter exception in stderr. No real RF reception asserted.
- Host CPU probe: processing a 1 MiB 250 kS/s CU8 capture interpolated into 2.5 MS/s with the same receiver harness used 0.285 s user CPU with rtl_433 attached vs 0.142 s inactive, for ~2.10 seconds of source IQ. This is a host-only, single-capture estimate (not an arm64 underrun measurement).
- Android arm64 release APK: 20,128,171 bytes vs 19,130,027 bytes in the existing main-checkout APK, +998,144 bytes. The baseline is an existing build artifact, not a fresh clean baseline build. Final debug APK: 173,023,550 bytes vs 172,071,834 bytes in that checkout (+951,716 bytes); debug artifacts can vary with build settings/caches.
- `lsusb` listed no `0bda:2838` device, so actual Linux Blog V4 messages and post-switch WAV/audio acceptance are NOT VERIFIED. Phone was not touched.
