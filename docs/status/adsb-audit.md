# ADS-B source audit and embedding plan

Scope: FlightAware `dump1090` at `0339a57b89cd6e61856cbb13ae342c31ae7be5ac` (`<refs>/openwebrx/ext/dump1090`) and OpenWebRX+ at `f1e0d1a` (`<refs>/openwebrx/openwebrx-plus`). This is a source/feasibility audit, **not** a working ADS-B decoder.

## Actual OpenWebRX+ behavior

- `owrx/modes.py:320-329` defines the `adsb` service mode over `empty`, no bandpass, `ifRate=2400000`, no squelch or secondary FFT. The client selector's fixed-rate secondary path is in `owrx/dsp.py:161-210`. `csdr/chain/aircraft.py:58-79` accepts **2,400,000 complex samples/s** and runs `Convert(COMPLEX_FLOAT, COMPLEX_SHORT)`, `Dump1090Module(rawOutput=True, jsonFolder=dirname(jsonFile))`, then `AdsbParser`. The float-to-short conversion multiplies each I/Q component by `SHRT_MAX` (`csdr/src/lib/converter.cpp:51-55`); this is interleaved signed 16-bit complex IQ, not audio, CU8, or SC16Q11. The downstream dump1090 `SC16` converter expects little-endian I/Q shorts, 4 bytes/complex sample, and magnitude `min(65535, 2*sqrt(I²+Q²))` in its generic exact implementation (`sdr_ifile.c:143-149`, `convert.c:40-56`, `dsp/impl/magnitude_sc16.generic.c:5-21`). Preserve conversion scale/clipping and compare chosen DSP flavor's output, rather than assuming a generic float magnitude is bit-identical.
- `csdr/module/aircraft.py:30-51` invokes the **external executable** with `--ifile - --iformat SC16 --lat <receiver_gps.lat> --lon <receiver_gps.lon> --modeac --metric`. Normally `jsonFile=/tmp/dump1090/aircraft.json`, hence `jsonFolder=/tmp/dump1090`; successful folder creation appends `--quiet --write-json <folder>`. Although `rawOutput=True`, `--raw` is appended **only if `jsonFolder is None`**: the normal aircraft UI reads periodic `aircraft.json`, not raw Mode S lines. If no JSON folder is provided the raw fallback cannot feed `AdsbParser`, whose `parseAircraft` always returns `None` (`owrx/aircraft/__init__.py:657-700`). `--modeac` enables Mode A/C demodulation; `--metric` affects dump1090 presentation, not the original JSON altitude/speed fields. The chain does not add `--fix` or `--fix-2bit`: `Modes.nfix_crc` defaults to zero (zero-initialized in `dump1090.c:108-115`, options at `:623-633`); DF correction defaults on if correction is enabled. Do not claim one-bit correction is OpenWebRX+'s default. Expose it as a separately tested option if desired; keep CRC rejection/filtering in every setting.
- `dump1090.c:153-212, 890-908` uses 2.4 MS/s, overlapping magnitude blocks (trailing preamble + long frame + 16 samples), `demodulate2400` and optionally `demodulate2400AC`. The main loop calls `backgroundTasks` for tracking/filter expiry, but **skips `trackPeriodicUpdate()` for `SDR_IFILE`** (`:466-472`). The embedded live receiver must explicitly call `icaoFilterExpire()` and `trackPeriodicUpdate()` on its wall clock; do not copy the file-input exception. `demod_2400.c:374-422` forwards accepted decoded messages to `useModesMessage`, which calls `trackUpdateFromMessage` in `mode_s.c:2274-2294`. Avoid emitting one event per raw frame to Dart.
- `net_io.c:1732-1875` produces `aircraft.json`: it emits **reliable** tracks only, `now` in epoch seconds, lowercase six-digit `hex` (possibly `~` for non-ICAO addresses), optional values only when their validity has not expired, and `messages`, `seen` (seconds since last message), and `rssi` (dBFS from an eight-message power history). `track.h:54-74,301-309` gives reliable-track TTL 300 s, unreliable TTL 60 s, position TTL 60 s, and reliability thresholds 2 DF17 / 3 DF11 / 5 any; `track.c:97-134,1375-1462` has per-field expiries (typically 70 s) and periodic pruning. Do not use a single made-up expiration for all fields.
- `AdsbParser` checks file mtime every second, reads `now` and `aircraft`, skips entries whose `ts = now - entry["seen"] <= lastParse`, then sets `lastParse = now` and publishes `{"mode":"ADSB-LIST","aircraft": AircraftManager.getData("ADSB")}` only when non-service and the parsed file has entries (`owrx/aircraft/__init__.py:677-799`). It uppercases `hex` to `icao`, uses `round(ts*1000)` as epoch-ms timestamp, `messages -> msgs`, `rssi` unchanged, looks up ICAO-derived country/registration (`:200-214`); copies lat/lon only together, strips flight, copies category/squawk and non-`none` emergency (uppercased). Altitude prefers `alt_geom`, then `alt_baro` (`"ground" -> 0`); vertical speed prefers `geom_rate` then `baro_rate`; speed prefers `gs`, `tas`, `ias`; course prefers `true_heading`, `mag_heading`, `track`; temperature prefers `oat`, then `tat`. Numerical altitude/speed/course/rate use Python `round` (ties-to-even), not simple integer truncation. All values are optional. `AircraftManager` keys by ICAO ahead of registration/flight, merges identifiers, updates only for newer timestamps, adds configurable `adsb_ttl`, cleans every 60 s, and filters ADSB entries in `getData` (`owrx/aircraft/manager.py:106-115,128-143,149-259`). An in-process bounded snapshot is a deliberate transport adaptation, not byte-for-byte OWRX pickle or global map/reporting parity.

## Source boundary and dependencies

Keep the upstream C algorithms: `demod_2400.{c,h}` (2.4 MS/s pulse demod, optional A/C), `mode_s.{c,h}` (message/ADS-B decode and dispatch), `crc.{c,h}` (syndromes, optional 1/2-bit correction), `cpr.{c,h}` (global/local positioning), `track.{c,h}` (reliability, CPR, lifecycle), `comm_b.{c,h}`, `ais_charset.{c,h}`, `mode_ac.{c,h}` (because `--modeac` is explicitly on), `icao_filter.{c,h}` (Mode S address trust), and `util.{c,h}` (clock/message time and helpers); `stats.{c,h}` if retaining native counters. Also keep `dump1090.h`, `dsp-types.h`, `compat/compat.h`, and the required DSP magnitude implementation. `convert.{c,h}` calls the generated `starch_magnitude_sc16` dispatcher: use `dsp/generated/{flavor.generic,dispatcher,starch.h}` plus its included `dsp/impl/*.generic.c` and `dsp/helpers/tables.c`; choose the pinned armv8 NEON flavor only after cross-build and oracle checks. Generated flavor includes implementation files; do not compile those again as independent objects. The upstream `Makefile:208-218` lists additional executable objects; this is **not** a linkable library target as-is.

Object-level check: `demod_2400.o` also references `adaptive_update` from `adaptive.c`, and `mode_s.o` references `modesQueueOutput` from `net_io.c`; `track.o` depends on `Modes`, `_messageNow`, `mstime`, CPR and Mode A/C. `adaptive.c:225-228` returns immediately when adaptive burst/range control is disabled (the OpenWebRX+ invocation does not enable either), but the full file also references tuner gain APIs. Provide a documented no-op `adaptive_update` adapter **only** for disabled control, or isolate the upstream function without its tuner hooks; never allow decoder-initiated gain changes. These are real link seams, not a reason to replace the core algorithm.

Exclude `dump1090.c` (main, CLI, signals, reader loop), `sdr*.c`, `fifo.c` (SDR acquisition/FIFO), `net_io.c` and `anet.c` (network, HTML and file JSON output), `interactive.c` (ncurses), `view1090.c`, `faup1090.c`, `public_html/`, `oneoff/`, and benchmark programs. Move only the minimal `Modes` initialization/defaults, timestamps, background expiry, and `useModesMessage` dispatch out of executable-specific code into a **thin in-process adapter**; the latter is currently implemented in `mode_s.c` but calls display/network paths (`mode_s.c:2274-2294`), so retaining that file unchanged without resolving its output references is not sufficient. A bounded serializer must reproduce the relevant `generateAircraftJson` field-validity/reliability rules without compiling the whole `net_io.c`; compare its output to upstream JSON. Preserve the global `Modes` state only with explicit single-instance ownership, reset/cleanup, and thread confinement; do not pretend it supports parallel receivers.

License: upstream `LICENSE:1-14`, `COPYING`, and individual file headers say GPL-2.0-or-later and include earlier BSD-style attribution. Selecting GPL-3.0-or-later for the combined AirSDR work is compatible with the `or later` grant; retain the complete upstream GPL text, license/attribution notices, provenance and source/modification availability for distributed Android/Linux binaries. Do not vendor executable assets, but do not strip copyright notices from kept files.

## Concrete integration blockers and ordered plan

1. **Current tap is not 2.4 MS/s.** `native/src/sdrcore.cpp:1135-1142` allows `raw_iq` only at an *exact* descriptor-required source rate. `native/src/dsp/receiver.cpp:320-336,375-409` nevertheless routes every attached decoder through an rtl_433-specific ~250 kS/s decimator and 0.4-rate low-pass. This destroys ADS-B pulses, even with `raw_iq` metadata. Extend the receiver to dispatch `Input::raw_iq` from the user-tuned, frequency-shifted CU8 branch **without decimation**, at 2.4 MS/s, or add a separately verified high-rate native resampler for other source rates. No tuner takeover, no second USB handle, no IQ via Dart; reject mismatched rates as not-ready until resampling is proven. Retune, rate change, stop and generation changes reset overlap/track state. Only one decoder runs.
2. **In-process link seam is nontrivial, but no licensing blocker identified.** `dump1090.c` owns `Modes` init/config and expiry; `mode_s.c` also contains display code and `useModesMessage` referencing external output; JSON generator lives in network/file `net_io.c`. Use a small patched vendored `mode_s.c` or narrow conditional compilation to bypass display/network references, retaining the decoding functions and tables; resolve the disabled-only `adaptive_update` link seam without exposing SDR gain control. Adapter initializes 2.4 MS/s, CRC tables (default `nfix_crc=0`), ICAO filter and Mode A/C tables; feeds the exact SC16 magnitude and overlapping `mag_buf` to `demodulate2400`/`demodulate2400AC`. Clock source must reflect live processing; serialize only reliable aircraft with validity checks. Do not rewrite demod/CRC/CPR/tracking as a simplified decoder.
3. Define a versioned settings/snapshot contract with the downstream decoder contract: `adsb`, `Input::raw_iq`, required 2,400,000 complex samples/s, nonexclusive/additive, `Result::aircraft`; optional receiver lat/lon only when explicitly configured (needed for surface/local CPR), optional correction setting with exact default, 1 Hz bounded snapshot, explicit `icao`/`flight`/`squawk`/`altitude`/`vspeed`/`speed`/`course`/`lat`/`lon`/`msgs`/`rssi`/`seen` and valid/missing semantics, plus separately named message/correction counters. Do not silently convert upstream units: dump1090 JSON altitude is feet, speed knots, vertical rate ft/min; `--metric` is display-only. The UI may format units explicitly. Keep raw address types (`~` non-ICAO) and Mode A/C behavior honest.
4. Test before wiring UI: original host `dump1090 --ifile <SC16> --iformat SC16 --modeac --metric --lat ... --lon ... --quiet --write-json ...` against the embedded backend **on identical IQ**. Compare decoded ICAO set, validity-gated fields, position, timestamps with tolerance for replay clock, correction modes and expiry; use original `cprtests` and generated/recorded license-permitted IQ for CRC/CPR, pulse overlap, Mode A/C and reset cases. No recorded IQ, cross-compiled arm64 link, end-to-end oracle or live RF comparison has been verified by this audit; those are gates for implementation, not evidence of current parity.

Feasibility checked here: 14 relevant upstream C translation units passed host `cc -std=c11 -D_POSIX_C_SOURCE=200112L -D_DEFAULT_SOURCE -DSTARCH_MIX_GENERIC -I. -fsyntax-only`. The upstream `cpr.c` and `cprtests.c` compiled into a local host test binary and all printed CPR cases passed (global airborne/surface and relative). This establishes source buildability on this Linux host, **not** a complete isolated in-process link, Android NDK build, or demodulation parity. The existing build's `cprtests` executable was absent, so the test was built inside this task's workspace.
