# LoRa / Meshtastic upstream verification and porting feasibility

Card t_21d361f6. Research only: no code changed. All results below come from
real runs on the Linux host (2026-10-11), unless explicitly marked unverified.

## 1. OpenWebRX+ reference chain (openwebrx-plus @ f1e0d1ac7dfa)

- Mode: `owrx/modes.py` `DigitalMode("meshtastic", underlying=["empty"],
  bandpass=None, ifRate=1000000, requirements=["meshtastic"], service=True,
  squelch=True)`. Feature `meshtastic` = `lorarx` binary + `py_meshtastic`
  (`owrx/feature.py`, `lorarx -h` must run).
- IQ: 1 MS/s complex float32 (`Format.COMPLEX_FLOAT`) from the selector,
  piped to stdin. No bandpass; the decoder does its own FIR/decimation
  (`FIR length=64 ratio=4` at bw 250 kHz).
- Exact command (`csdr/module/lora.py` + `csdr/chain/lora.py`
  `MeshtasticDemodulator`):

      lorarx -i /dev/stdin -r 1000000 -f f32 -v -N -Q \
             -H 5 -W 50 -b <meshtastic_bw> -s 7 -s 8 -s 9 -s 10 -s 11 \
             -j /dev/stdout

  `-v` verbose, `-N` newline + verbose, `-Q` quiet on CRC errors,
  `-H 5` hex-format level, `-W 50` auto-notch interval, `-b` bandwidth
  index, `-s` one demodulator per SF (7..11, parallel), `-j` JSON sink.
- Bandwidth index (`owrx/form/input LoraBandwidthInput`):
  0=7.8, 1=10.4, 2=15.6, 3=20.8, 4=31.25, 5=41.7, 6=62.5 (VeryLongSlow),
  7=125 (MediumSlow/LongModerate/LongSlow), 8=250 (ShortSlow/MediumFast/
  LongFast, default), 9=500 kHz (ShortFast). One bw per decoder instance;
  presets differ only by bw + SF, all SF 7..11 are tried concurrently.
- Default frequencies (bands-r*.json): EU868 869.525 MHz, US915 906.875 MHz,
  AU915 919.875 MHz (Meshcore 869.618 / 910.525 / 916.575).
- Other LoRa chains for later reuse: LoRaWAN `-H 5 -b <bw> -s ±7..±12`,
  LoRa-APRS `-H 5 -W 50 -b 7 -s 9 -s 12`, FANET `-H 5 -b 8 -s 7`,
  Meshcore `-H 5 -W 50 -b <bw> -s 7 -s 8`, MeshCom `-H 1 -W 50 -b <bw> -s 10 -s 11`.
- Parser: `owrx/meshtastic.py MeshtasticParser.parse()` takes one JSON line,
  ignores lines that do not parse, base64-decodes `payload`, parses the 16-byte
  header (dest, src, id, flags, channel hash at byte 13), dedups by
  (src, id), tries channel keys whose hash matches, AES-CTR decrypts and
  decodes `portnums_pb2`. Already ported natively in master as
  `sdrcore_meshtastic` (docs/status/meshtastic.md, card t_a68f364b).
- lorarx JSON fields (author-hosted `loraprotocols.c sendjson`): `net crc
  invers bw sf cr preamb duration level afc dre eye eyemin nfloor pknfloor
  snr snrmin fec firlen notches chirps rxmhz ver payload` (some only when
  present). `crc`: 1 ok / 0 bad / -1 none.

## 2. Upstream lorarx source: two divergent copies

| Source | Status for OWRX+ command |

| GitHub mirror `oe5hpm/dxlAPRS` @ 10bec72314d8 `src/lorarx.c` (4835 lines, single file, links `fft.o complex.o` + `OBJ_COMMON`) | Built from source OK. **Rejects** `-H 5` (`>5< use -h`; `-H` takes no argument) and **has no `-j`** (`>-j< use -h`). Not usable for parity. |
| Author site `http://oe5dxl.hamspirit.at:8025/aprs/c/` `lorarx.c` (dated Sep 25 2026, sha256 e7c49ac8…) + `loraprotocols.c/.h` (sha256 775b92dc…) | Has `-H <n>`, `-j <pipe/file>`, JSON in `loraprotocols.c`, a built-in Meshtastic header print. This is what OWRX+ packages. |
| OWRX+ PPA `dxlaprs-lora_1.0.20260515_amd64.deb` (sha256 32a57f19…, matches PPA index); changelog: "Automated build from http://oe5dxl.hamspirit.at:8025/aprs/c/" | Runs the exact OWRX+ command successfully (see §4). |

The author files were captured through the browser (curl to port 8025 timed
out), so their exact bytes are unconfirmed against a second channel.

Dependencies of the author version: `X2C.h` (XDS Modula-2 → C runtime
macros), `osi.c/osic.c` (file IO, alloc, args), `aprsstr.c` (strings),
`udp.c` (AXUDP/JSON-UDP outputs), `mlib.h`, `loraprotocols.c`, libm, signal.
No FFTW (own radix FFT in `lorarx.c`). Code is machine-translated Modula-2:
global state, `static` functions, X2C idioms.

## 3. Licence (authoritative evidence)

- GitHub mirror: `src/lorarx.c`, `src/loratx.c` carry
  `SPDX-License-Identifier: GPL-2.0+`, Copyright Christian Rabler (OE5DXL);
  repo `license-header.txt` is the same header; neither file is in
  `license-exclude.txt`.
- Author site `Licenses/README` (by OE5DXL): the whole toolchain is GPL v2,
  "Most of it can also be distributed, at your option, under any later
  version … see individual files for exceptions"; `Licenses/Exceptions`:
  "there currently are no exclusions". Author-site `lorarx.c` and
  `loraprotocols.c` have no per-file header (only "Generated by XDS
  Modula-2 to ANSI C").
- AUR `dxlaprs-lora-git` packages lorarx as `GPL-2.0-or-later`.
- Conclusion: GPL-2.0-or-later → compatible with this project's GPL-3.0.
  Residual risk: the newer `loraprotocols.c` has no SPDX line; the
  toolchain-wide README + empty Exceptions cover it. When vendoring, add
  the GPL-2.0+ header with a pointer to that README and keep a NOTICE entry.

## 5. Can the decoder be embedded without the executable / IO layer?

Yes, with a mechanical refactor; no algorithm rewrite needed:

1. Vendor author-site `lorarx.c`, `loraprotocols.c/.h`, `X2C.h`, the
   needed parts of `osic/osi/aprsstr` under `native/third_party/dxlaprs/`
   with recorded source URL, date and sha256.
2. Replace `main`/arg parsing with an init function that builds the same
   demod bank from (bw index, SF list, -W, -H, -Q), i.e. reuse the existing
   option code path with a synthetic argv, to keep parity.
3. Replace the `osi_RdBin(iqfd…)` read loop (author `lorarx.c` ~2542) with a
   `push(const float* iq, size_t n)` that feeds the same buffer logic.
4. Replace `sendjson` file/UDP output with a callback delivering the JSON
   line (or struct) to `sdrcore_meshtastic`; stub `udp.c`, drop signals.
5. Global state ⇒ one instance per process. Acceptable under the
   one-receiver invariant; reset must reinitialise all globals.
6. The IQ tap must deliver 1 MS/s complex float at the tuned frequency;
   high-rate IQ stays in C (AGENTS.md).

Effort/risk: moderate. X2C idioms and globals make tests important: the
acceptance test is byte-identical JSON (except timing fields) between the
embedded decoder and the packaged binary on the same IQ file.

## 6. Fidelity gaps and risks

- Upstream drift: the author site changes without git history; pin by sha256
  and keep a copy of the fetched sources in-tree.
- Only one synthetic SF11/250 kHz packet verified; other presets
  (SF7–10, bw 125/500/62.5) and implicit-header/inverted cases unverified.
- CPU on Android for five parallel SF demods at 1 MS/s: unmeasured.
- Packaged binary prints `snr:11.7/9.8dB q:99/98%` vs mirror `snr:12.2dB
  q:84%` — the algorithms differ between versions; parity must target the
  author-site version.

## 7. Alternatives (not chosen)

gr-lora_sdr (EPFL, GPL-3.0) is GPL-3-compatible but depends on GNU Radio
blocks; porting is larger and would not give OpenWebRX+ parity. Decision:
embed author-site lorarx (GPL-2.0+); no substitute PHY is implemented.
