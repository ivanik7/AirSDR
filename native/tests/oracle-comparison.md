# N1 host ABI tests and source comparisons

Run `native/tests/run_host_tests.sh <scratch-build-dir>` on Linux. It builds the real source-linked `libsdrcore.so`, executes the five CTest ABI/stream/fd/checksum/ring cases, the direct fd and checksum programs, and two original-C checks. CTest drives actual ABI entry points for version/layout, argument boundaries and units, open failure and state, file/synthetic streaming, counter accounting, fd borrowing and double-close, and callback teardown through an injected internal adapter. The extra source-level fault test links the pinned `libsdrcore_rtlsdr.a` and wraps `libusb_init` to return `LIBUSB_ERROR_NO_MEM`; `rtlsdr_create_device` must free its allocation, clear the output pointer, and preserve the error. The fault test is run by the script but still needs a CMake CTest registration by the integration owner (see board task t_52871d87).

The runner compiles the vendored RTL-SDR C sources against the existing oracle's fake libusb and drives `tool/oracle/rtlsdr/scenarios/blog_v4.txt`. It compares the resulting control-transfer trace byte-for-byte with `tool/oracle/rtlsdr/golden/blog_v4.trace`, generated from the original osmocom C implementation. On the host run the traces matched (659 lines). This validates the common Blog V4 initialization/tuning code path under scripted libusb responses; the Android open-by-fd patch, USB transfers, physical RF reception and actual callback timing are not represented by this oracle. The file-source checksum test independently calculates FNV-1a for generated CU8 samples, including odd input and a 64 KiB file; sample equality is asserted only after the consumer has drained. The source-level callback test checks that no callback fires after the blocking adapter's `stop` joins; it cannot prove hardware libusb callback teardown. HackRF's existing C oracle fake-libusb header does not provide `libusb_wrap_sys_device`, so its patched source does not compile under that oracle without extending the fake. No HackRF trace comparison is claimed here.

The socket RST and subsequent file reopen test simulates an abnormal host input error and recovery, **not** Android USB detach/replug. Real fd handoff and Blog V4 detach/replug require the phone gate. No native DSP, demodulation, or audio is tested at N1.
